# OR-Scheduling-Saas
Project with Hermes Agent: From First Principles to Scheduling SaaS Delivery

## 项目简介

本项目为 SaaS 调度优化平台的**核心算法引擎内核**，采用「先独立开发、后平台接入」的渐进式开发模式。项目并非针对单一业务场景的定制化调度算法，而是一套可配置、可扩展、可独立运行的通用调度求解基础设施，支持通过配置快速生成多场景调度模型，内置标准化输入输出协议，后续可通过新增适配层无缝接入 SaaS 平台，核心代码零重构。

### 设计理念

- **公式先行**：所有约束与目标均对应标准数学定义，建模逻辑与公式一一映射

- **配置驱动**：通过元数据配置动态生成模型，不硬编码业务规则

- **框架通用**：一次框架搭建，多场景复用，支持快速扩展新约束、新目标、新求解器

- **预留接入**：接口规范、数据协议、错误码体系与 SaaS 平台完全对齐，后续接入成本极低

## 核心特性

### 1\. 通用元数据建模体系

- 内置工件、工序、机器、辅助资源、人员五类通用调度实体

- 支持实体自定义扩展字段，不影响核心建模逻辑

- 所有约束、目标均抽象为可配置组件，参数化开关与调整

### 2\. 内置约束组件库

|约束类型|说明|
|---|---|
|工艺顺序约束|同一工件工序间的先后依赖关系|
|机器独占约束|同一机器同一时间仅可加工一道工序|
|时间窗约束|工序可加工的最早 / 最晚时间范围|
|资源容量约束|共享资源的同时使用数量上限|
|工序指派约束|指定工序仅可在指定机器上加工|
|不可中断约束|工序一旦开始加工不可暂停|

### 3\. 内置目标函数库

支持多目标线性加权组合，可动态配置权重：

- 最小化最大完工时间（Makespan）

- 最小化总加权完工时间

- 最小化总加权拖期时间

- 最小化机器切换成本

### 4\. 多求解器统一适配

- 默认适配 **OR\-Tools CP\-SAT**，可选适配 Gurobi

- 对外提供完全一致的调用接口，上层无需感知底层求解器差异

- 严格对齐求解器官方最新 API 规范，内置版本管理

- 预留灰度切换能力，支持按任务 / 租户切换求解器

### 5\. 预制场景模板

内置 3 个高频场景预制模板，上传数据即可直接求解：

- 流水车间调度模板

- 柔性作业车间调度模板

- 并行机调度模板

### 6\. 多形态调用入口

- **Python SDK**：可直接集成到业务脚本中调用

- **命令行工具**：适合批量测试与离线计算

- **HTTP 同步接口**：RESTful 风格，接口规范与 SaaS 平台完全对齐

### 7\. SaaS 接入预留设计

- 接口预留 `tenant_id` / `task_id` / `user_id` 字段，一期透传不处理

- 内置标准化任务状态定义与进度输出机制

- 统一错误码体系，对齐 SaaS 平台告警规范

- 核心引擎无全局状态，天然支持租户数据隔离

## 快速开始

### 环境要求

- Python 3\.9\+

- OR\-Tools \>= 9\.10（默认依赖）

- Gurobi（可选，需自行安装激活）

### 安装

```bash
# 安装 SDK
pip install scheduler-engine
```

### 最小示例：并行机调度

```python
from scheduler_engine import SchedulerEngine, Template

# 1. 加载并行机调度预制模板
engine = SchedulerEngine(template=Template.PARALLEL_MACHINE)

# 2. 输入业务数据
data = {
    "jobs": [
        {"id": "J1", "processing_time": 3, "weight": 2},
        {"id": "J2", "processing_time": 2, "weight": 3},
        {"id": "J3", "processing_time": 4, "weight": 1},
        {"id": "J4", "processing_time": 1, "weight": 4}
    ],
    "machines": [
        {"id": "M1"},
        {"id": "M2"}
    ]
}

# 3. 配置求解参数
config = {
    "solver": "cp_sat",
    "max_time_seconds": 60,
    "gap_threshold": 0.01
}

# 4. 求解并获取结果
result = engine.solve(data, config)
print(f"最优目标值：{result.objective_value}")
print(f"调度方案：{result.schedule}")
```

## 调用方式

### 1\. Python SDK

适合集成到业务系统、脚本化调用，详见 `docs/api_reference.md`。

### 2\. 命令行调用

```bash
# 命令行求解示例
scheduler-engine solve \
  --template parallel_machine \
  --data examples/data/pm_example.json \
  --config examples/config/default.json \
  --output result.json
```

### 3\. HTTP 接口调用

```bash
# 启动本地接口服务
scheduler-engine serve --port 8080

# 调用求解接口
curl -X POST http://localhost:8080/api/v1/solve \
  -H "Content-Type: application/json" \
  -d '{
    "template": "parallel_machine",
    "data": {...},
    "config": {...},
    "tenant_id": "t001",
    "task_id": "task001"
  }'
```

> 接口请求 / 响应格式与 SaaS 平台规范完全一致，后续接入仅需转发请求至 SaaS 网关。

## SaaS 平台接入说明

本项目内核已完成所有前置适配设计，接入 SaaS 平台无需重构核心代码，仅需新增适配层。

### 接入改造点

1. **新增异步任务适配层**：对接 SaaS 任务队列，将同步调用封装为异步任务

2. **对接进度推送**：内核已内置进度回调，直接对接平台 WebSocket 推送服务

3. **接入多租户路由**：内核已支持 tenant\_id 透传，仅需在网关层增加路由与隔离逻辑

4. **结果持久化**：按平台数据规范将求解结果写入数据库

### 详细接入指引

参见完整文档：`docs/saas_integration_guide.md`，包含：

- 分步接入操作手册

- 适配层示例代码

- 接口字段映射关系

- 错误码对齐说明

- 预估工作量与排期参考

## 扩展开发指引

### 新增一个约束组件

1. 在 `scheduler_engine/metadata/constraints/` 下新增组件类，继承基类

2. 实现参数校验、数学定义、模型生成逻辑

3. 注册到组件管理器

4. 补充对应单元测试

### 新增一个场景模板

1. 在 `scheduler_engine/templates/` 下新增配置文件

2. 配置默认约束组合、目标函数、求解参数

3. 补充示例数据与测试用例
