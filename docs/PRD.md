## 一、产品概述

**OR-Scheduling-SaaS** 是一套面向车间排产 / 手术排程场景的**多机台智能排产 SaaS 平台**：

- **求解内核**：OR-Tools CP-SAT 精确求解 + 自研构造启发式 / ALNS 元启发，按数据规模自动路由；
- **业务问题**：并行机调度 + 序列相关切换时间 + 机器-配方兼容性 + 三目标加权（makespan / 总延误 / 总完工时间）；
- **产品形态**：FastAPI 后端 + RQ 异步 Worker + React 前端，Docker Compose / Kubernetes 双部署形态，多租户 + JWT/API Token 双通道鉴权。

### 解决的问题

车间排产普遍依赖人工经验表格，切换时间、交期冲突、产能过载等要素难以统筹，排产结果质量不稳定、不可复现。本产品将排产问题形式化为数学规划模型，提供**可上传数据 → 自动建模求解 → 可视化排程结果**的一站式 SaaS 服务，并保证**结果可验证、可追溯、可复现**。

### 核心价值

| 价值点 | 说明 |
|---|---|
| 数据决定模型 | 求解器/算法按订单规模自动路由（小规模精确最优，大规模元启发限时出解） |
| 结果可验证 | 四层测试体系 + 约束自动验证 + 求解日志全量留存 |
| 可视化决策 | 甘特图、负载分析、延误分析、瓶颈下钻 |
| 多租户隔离 | 数据按租户物理隔离，四级角色权限 |

## 三、核心业务场景

### 场景 1：排产任务全流程（主流程）

```
注册/登录 → 上传数据集（机台/订单/配方/切换矩阵/元数据 5 JSON）
→ 配置求解参数（权重 λ、求解器、时间预算）
→ 提交任务 → 异步求解（SSE 实时进度）
→ 查看结果 Dashboard（KPI/甘特图/求解日志/优化分析）
→ 按需导出或再次求解
```

### 场景 2：大规模产能过载下的排产

- 数据特征：load_factor > 1（产能过载，交期必然超期）→ 交期为**软约束**，目标以总延误 ΣT 为核心（默认 λ=(0,1,0)）；
- 平台保证：大规模（≥200 订单）限时出可行解并附质量指标（gap / 下界），不做虚假"最优"宣称。

### 场景 3：高冲突切换约束

- 部分配方对**不可直接切换**（null），可经中间配方绕行；
- 平台保证：高 null 比例数据不崩溃、解可行（L2 边界测试 + 单元测试覆盖 8 null 场景）。

## 五、算法需求（核心口径）

### 1. 问题定义

| 要素 | 定义 |
|---|---|
| 问题类型 | P_m \| M_j, s_uv \| λ₁C_max + λ₂ΣT_j + λ₃ΣC_j |
| 集合 | 订单 J（n）、机台 M（m）、配方 R；机台 m 可加工配方集 R_m |
| 参数 | p_j = quantity_j × processing_time(recipe_j)（整单不可拆分）；交期 d_j；机台清理 c_m；切换 s_uv（null=禁止，可绕行） |
| 决策变量 | x_jm ∈ {0,1} 分配；S_j 开工；C_j 完工；T_j 延误 |
| 目标 | min λ₁C_max + λ₂ΣT_j + λ₃ΣC_j，λ 用户定义，默认 (0,1,0) |
| 约束 | (2) 每订单恰一机台；(3) 机器-配方兼容；(4) NoOverlap；(5) 切换+清理（null 绕行）；(6) 延误定义；(7) 不可中断 + makespan 定义 |

### 2. 关键业务口径（数据体检结论）

1. **订单不可拆分** → 建模粒度 = 整单；
2. **load_factor > 1（产能过载）** → 交期软约束，makespan 必超计划周期，ΣT 为核心目标；
3. **priority 忽略**（D1）→ 不进目标、不作为权重，仅展示；
4. **null = 禁止直接切换，可经中间配方绕行**（切换次数 ≤ n−1）。

### 3. 复杂度与求解策略

- 整体**强 NP-难**（ΣT_j 单机即 NP-难 + 序列相关 setup 使单机排序退化为非对称 TSP）；
- 求解器路由（数据决定模型，实测校准）：

| 订单数 n | 策略 | 对应测试层 |
|---|---|---|
| n ≤ 20 | CP-SAT 精确 | L1（5 单）/ L2（12 单） |
| n ≤ 80 | 构造 + ALNS 300s | L3（50 单） |
| n ≤ 300 | 构造 + ALNS 900s | L4（200 单） |
| else | 构造 + ALNS 900s | L5（500 单） |

> 选型依据（实测）：L3 medium 实例 CP-SAT 300s 得 ΣT=7828（gap 90%），构造+ALNS 60s 得 ΣT=7280（更优）→ L3 由 CP-SAT 时间限改为元启发。

### 4. 五层测试验收标准

| 层级 | 规模 | 验收标准 | 结果（实测） |
|---|---|---|---|
| L1 toy | 3 机 × 5 单 | 必须正确解（手工可验证） | ✅ OPTIMAL，0.008s，gap=0 |
| L2 boundary | 4 机 × 12 单（8 null） | 高不可切换比例不崩溃 | ✅ OPTIMAL，24.7s，gap=0 |
| L3 medium | 8 机 × 50 单 | 5 分钟内出解 | ✅ FEASIBLE，300s（ALNS 7292 vs CP-SAT 7828） |
| L4 large | 20 机 × 200 单 | 15 分钟内出解 | ✅ FEASIBLE，900s |
| L5 massive | 30 机 × 500 单 | 可用解 + 质量报告 | ✅ 构造 0.3s + ALNS 234.8s，makespan −8.3% |
