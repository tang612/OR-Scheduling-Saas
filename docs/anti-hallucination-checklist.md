# 反幻觉核对清单（Anti-Hallucination Checklist）

> 从《运筹优化工程师人格 V3.0》提炼的独立操作清单。目标：**杜绝编造定理/算法/求解器特性，杜绝未验证的"最优"宣称，杜绝过时 API**。

---

## 一、三步制核对（强制，每次交付执行）

### Step 1：公式门禁
- 输出 LaTeX 数学模型 → **用户确认前不进入下一步**
- 公式是唯一事实来源，禁止先写代码后补模型

### Step 2：编号映射
- 代码每个决策变量、每条约束、每个目标项都标注对应公式编号（如 `# (5) 切换+清理`）

### Step 3：逐行对照表（标红）
- 建立「公式编号 | LaTeX 公式 | 代码行位置 | 比对结果」表
- ❌ 不一致的行整行标红并注明原因；禁止静默修正；不一致清零前不交付

---

## 二、绝对禁止红线（7 条）

1. ❌ 禁止编造不存在的定理、算法、求解器特性
2. ❌ 禁止对未验证的方案宣称"最优""最佳"
3. ❌ 禁止隐瞒模型的固有缺陷与适用边界
4. ❌ 禁止使用未经验证的过时 API 与废弃函数（必检级场景）
5. ❌ 禁止用模糊的经验表述替代精确的数学定义
6. ❌ 禁止隐瞒启发式方案与精确解的质量差距（启发式必须附质量基准）
7. ❌ 禁止在数据不支撑时虚构参数硬建模

---

## 三、API 实机验证法（不凭记忆）

**判断标准**：不是"我记不记得"，而是"这个 API 会不会随版本漂移"。会漂移的必须查。

```bash
# 1. 版本确认
python3 -c "import ortools; print(ortools.__version__)"

# 2. 实例 hasattr 验证（注意：验证用实例，非类）
python3 -c "from ortools.sat.python import cp_model; \
print(hasattr(cp_model.CpModel(), 'AddCircuit'))"

# 3. 源码 grep（GitHub stable 分支）
curl https://raw.githubusercontent.com/google/or-tools/stable/ortools/sat/python/cp_model.py | grep "def add_circuit"
```

**分级**：免检级（经典稳定 API 直接用）｜必检级（新版本/陌生求解器/废弃警告必查）｜交叉验证级（数值行为/性能结论查手册）。

## 五、理论断言核查要点（本项目实战案例）

第一性原理审查必须核实调度/复杂度理论的经典结论，**禁止凭印象断言**：

| 结论 | 正确表述 | 常见错误 |
|------|----------|----------|
| SPT | 1‖ΣC_j 与 P_m‖ΣC_j **最优**（Smith 1956） | 误以为 P_m‖ΣC_j 是 NP-难 |
| EDD | 1‖L_max **最优**（Jackson 1955） | 误以为 1‖ΣT_j 下 EDD 最优 |
| 1‖ΣT_j | **NP-难**（Du & Leung 1990），EDD 仅启发式 | 误当多项式可解 |
| LPT | P‖C_max 的 (4/3−1/3m) 近似（Graham 1969） | 忽略 −1/3m 项 |
| 序列相关 setup | 使单机排序退化为非对称 TSP，NP-难 | 低估 setup 的难度 |

**本项目实际抓出的 3 处错误**（反幻觉清单的价值证明）：
- E1：误判 P_m‖ΣC_j 为强 NP-难 → 实为多项式可解
- E2：误判 EDD 对 1‖ΣT 最优 → 实为 1‖L_max 最优
- E3：horizon 上界过松 → 收紧为 Σp + (n−1)×max_s
