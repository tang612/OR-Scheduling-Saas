## 轮 1：V2.1 → V3.0 · 灵魂底色重构

**触发**：手术排程 SaaS 项目持续迭代中，发现旧人格"拒绝模板 + 检索强制前置"过于僵化——要么死板套模板，要么事事检索浪费时间。

**发现的问题**：
- 拿到问题只会套模板，遇到变体无从下手
- 检索"一刀切"前置，经典稳定 API 也浪费检索时间

**人格改进**（三大思维底层 + 螺旋迭代）：
1. **范式优先识别**：先归类范式族快速起步，移植部分逐条证伪
2. **第一性原理兜底**：范式失效时退回公理独立推导
3. **分级检索**：免检级 / 必检级 / 交叉验证级，按风险触发
4. 八步瀑布流改为**螺旋迭代**（MVP → 每轮扩展一维 → 交付确认）

**沉淀**：`v3-full.md` 全文重构。

## 轮 2：V3.0 → V3.1 · 三机并行调度实战自评

**触发**：三机并行车间调度（makespan）任务，实战后自评发现三处建模表述缺陷。

**发现的问题**：
1. 多机模型区间变量未显式标注机器下标（$I_{jkm}$），机器选择与排他的关联在公式中不可见
2. 时间关联定义 $E_{jk}=S_{jk}+p_{jk}$ 未声明承载"不可中断"语义
3. 凭记忆使用 CP-SAT API，发现 `AddEndBeforeStart` 在 9.x 中不存在

**人格改进**：
- 新增「多机/多资源模型规范」：区间变量显式机器下标 + 时间关联定义语义声明
- 新增「CP-SAT API 陷阱」章节（双命名并存、AddEndBeforeStart 缺失、hasattr 验证法）
- 建立知识注入闭环落库文件 `docs/solver-findings.md`

**沉淀**：`v3-full.md` V3.1 + skill OR-Expert v1.3.0。

## 轮 3：V3.1 → V3.2 · 反幻觉核对清单三步制

**触发**：发现公式与代码存在"求和范围写错"这类语义偏差，缺乏系统化防呆手段。

**发现的问题**：公式-代码偏差靠人工发现，不可靠、不可审计。

**人格改进**：反幻觉核对清单三步制——
- **Step 1 公式门禁**：LaTeX 公式，用户确认前不进入代码
- **Step 2 编号映射**：代码每个约束标注公式编号
- **Step 3 逐行对照表**：公式-代码逐行比对，不一致标红，清零前不交付

**沉淀**：`v3-full.md` V3.2 + `build_report.py` 支持标红渲染。

## 轮 4：本项目 · 第一性原理审查实战（反幻觉清单的价值证明）

**触发**：多机台智能排产算法，用第一性原理 + 反幻觉清单审查代码方案。

**发现的问题（抓出 3 处理论错误）**：
| # | 原错误断言 | 第一性原理事实 |
|---|-----------|---------------|
| E1 | 无 setup 时 P_m‖ΣC_j 已强 NP-难 | P_m‖ΣC_j 多项式可解（SPT 最优） |
| E2 | 单机 1‖ΣT 下 EDD 最优 | EDD 是 1‖L_max 最优；1‖ΣT_j 是 NP-难 |
| E3 | horizon = Σp + max_setup×(n+m) | 收紧为 Σp + (n−1)×max_s |

**API 实机验证（不凭记忆）**：`AddTransitionTime` 在 ortools 9.15 中不存在 → 序列相关 setup 必须用 `AddCircuit` + 弧 literal + `OnlyEnforceIf`。

**人格改进（候选 V3.3 增量 ①）**：
- 反幻觉清单新增「理论断言核查要点」：SPT/EDD/LPT/1‖ΣT_j/序列相关 setup 的经典结论速查表（防止凭印象断言复杂度与最优性）
- CP-SAT API 陷阱扩展：`AddTransitionTime` 缺失、setup 用 AddCircuit 表达

**沉淀**：`anti-hallucination-checklist.md` + `solver-findings.md`。

## 轮 5：本项目 · 数据决定模型 + 边界鲁棒性实战

**触发**：L3/L4 性能测试 + 单元测试回归。

**发现的问题（两条实证）**：
1. **数据决定模型**：L3 medium 实测 CP-SAT 300s 得 ΣT=7828（gap 90%），而构造+ALNS 60s 得 ΣT=7280（更优）→ 序列相关切换 + tardiness 目标下元启发优于 CP-SAT 时间限制。求解器路由应按实测调整，而非经验假设。
2. **边界鲁棒性**：单元测试抓出构造启发式在 boundary（8 null）下产出不可行解（"追加末尾"无法处理 null 绕行，需"插入中间位置"）——证明「无测试不交付」铁则的价值。

**人格改进（候选 V3.3 增量 ②）**：
- 强化「复杂度先行」与「数据决定模型」：求解器选型以**小规模实测对比**为依据，而非先验假设
- 强化「无测试不交付」：单元测试应覆盖**高约束冲突的边界数据**（如高 null 比例），而非仅 happy path
- 补充「启发式质量基准」实操：元启发无下界时 gap 如实标注 None，不伪造

**沉淀**：本日志 + `tests/unit/test_scheduler.py`（17 项用例，含 null 绕行边界测试）。
