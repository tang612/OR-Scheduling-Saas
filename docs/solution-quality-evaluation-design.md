## 二、第一性原理审视

### 洞察 1：tardiness 目标的下界本质松（决定性）
- $T_j = \max(0, C_j - d_j)$ 的最小化核心是「排序以减少总延误」，组合优化核心（$1||\sum T_j$ 已 NP-难）
- 下界靠「放松机器容量」构造：$\sum_j \max(0, p_j - d_j)$，无法捕捉「排队延误」
- 推论：过载 tardiness 目标绝对 gap 必然松，L3 gap 90% 是「下界松」而非「解差」

### 洞察 2：gap 用途定位
| 用途 | 可靠？ |
|---|---|
| 横向对标 | ✅ 同一参考值，松紧一致 |
| 保守报告 | ⚠️ gap 虚高，需标注来源 |
| 精确终止 | ❌ 松下界 → 永远达不到阈值 |
| 相对改进率终止 | ✅ 不依赖下界 |

### 洞察 3：信号分层
- 强闭环：解属性指标 → ALNS 引导目标
- 外层闭环：参考解相对 gap + 相对改进率
- 绝对 gap 仅作保守报告

## 四、解质量评价体系

指标总表 7 项（GAP、目标函数值、可行性违反、耗时、稳定性、负载均衡、弹性），评分映射规则见 V1/V2。

GAP 三场景公式：
- 最优可得：$GAP_A=(obj-obj^*)/\max(|obj^*|,\epsilon)$
- 仅下界：$GAP_B=(obj-LB)/\max(|LB|,\epsilon)$
- 仅参考解：$GAP_C=(obj-obj_{ref})/\max(|obj_{ref}|,\epsilon)$（可为负）

综合评分：$Score = \sum_i w_i \cdot score_i, \sum_i w_i=1$

## 五、算法集成工程方案（去 SaaS）

```
算法求解层（遗传/模拟退火/禁忌/ALNS/CP-SAT）
      ↓ SolverResult { solution, objective, meta }
评测核心层（指标注册表 + 约束校验器 + 评分引擎）
      ↑ EvaluationConfig（阈值/权重/规则，本地配置）
```

- 指标可插拔：`Metric` 接口 + 注册表，不改核心框架
- 评估驱动迭代集成点：① ALNS 接受准则改多指标评分；② 相对改进率终止；③ 每次求解输出 7 项指标 + 参考值来源

## 六、迭代追溯机制与基准锁定（V3 新增，三目标的工程落点）

### 6.1 三目标落点

| 目标 | 落点 |
|---|---|
| 可量化 | 7 指标 + 综合评分 + Δ 增量（纯数值） |
| 可对比 | 基准锁定（四固定） |
| 可追溯 | version → change → commit → metrics → delta 链路 |

### 6.2 基准锁定（baseline lock）

**四固定**：同一实例 + 同一参考值 + 同一评测权重 + 同一 seed 集合。
任一变化 → 开启新基准线，旧数据标「不可比」，禁止跨基准线直接比较。

### 6.3 版本化评测快照（每轮迭代一条）

```json
{
  "version":   "v1.3.0",
  "change":    "ALNS 接受准则扩展为多指标评分",
  "commit":    "abc123",
  "instance":  "medium",
  "reference": {"type": "baseline", "value": 7828},
  "config":    {"lambda": [0,1,0], "weights": {}, "seeds": [42,43,44]},
  "metrics":   {"makespan": 933, "tardiness": 7292, "score": 0.83},
  "delta":     {"score": 0.02, "tardiness": -328},
  "timestamp": "2026-08-19T00:00:00Z"
}
```

### 6.4 增量追踪（delta tracking）

Δ = 本次指标 − 上次指标；进步为正、退化为负；**退化即拦截**（回归门禁，同 L1-L4 测试）。

### 6.5 关键约束（保证可对比不失效）

> **评测基准指标必须固定，算法引导目标可以演化**

- 评测永远用固定基准指标（makespan / ΣT / ΣC），不随迭代变
- 算法内部引导目标（λ 加权和 → 多指标评分）可自由演化
- 「固定尺子量」与「换算法内部目标」解耦，量出的进步才可对比
