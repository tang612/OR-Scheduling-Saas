## 一、总体架构

五层架构 + 异步求解数据流：

```
┌─────────────────────────────────────────────────────────────┐
│ 前端层  React SPA (Vite + TS)                               │
│  Dashboard / 参数表单 / 甘特图 / 日志 / 分析面板              │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTPS (nginx 8080/8443)
┌───────────────────────────▼─────────────────────────────────┐
│ API 网关  Nginx            TLS 终止 + 静态资源 + 反向代理      │
└───────────────────────────┬─────────────────────────────────┘
                            │ REST / SSE
┌───────────────────────────▼─────────────────────────────────┐
│ 业务逻辑层  FastAPI (backend/)                              │
│  auth(双通道) / datasets / tasks / solutions + 限流/指标     │
│        ▲                                        │           │
│        │ Redis: 队列 + 进度总线(pub/sub) + 取消标志        │
│        ▼                                        ▼           │
│ 业务逻辑层  Worker (worker/ RQ)                            │
│  RQ job → solver_service → scheduler 引擎路由               │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│ 求解器层  solver-core (scheduler 包)                        │
│  model 数据体检 → cp_sat 精确 → heuristics 构造+ALNS         │
│  → router 规模路由 → evaluation 评估 → visualize 可视化      │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│ 数据层  MongoDB 7 (任务/方案/数据集/用户/日志) + 持久化卷      │
└─────────────────────────────────────────────────────────────┘
```

**异步求解数据流**（SSE 四段式）：

```
前端 <──SSE── API <──Redis pub/sub── Worker <──RQ 队列── API (提交任务)
```

API 无状态可水平扩展：进度不落 API 内存，Worker 写 Redis pub/sub，API 订阅转发 SSE。

## 二、技术选型及理由

| 层 | 选型 | 理由（第一性原理审查后确立） |
|---|---|---|
| 求解内核 | OR-Tools CP-SAT 9.15 | 开源、Python 生态、约束规划对调度问题建模自然；官方 wheel 支持 cp314 |
| 元启发 | 自研构造 + ALNS | L3 实测优于 CP-SAT 时间限（数据决定模型）；大规模唯一可行路径 |
| 商业求解器 | Gurobi（仅留接口，默认不启用） | 需商业/学术 license；接口预留支持灰度切换 |
| API 框架 | FastAPI + Pydantic v2 | 类型安全（接口 I/O 严格建模）、原生异步、自动 OpenAPI 文档 |
| 数据库 | MongoDB 7 | 文档模型天然匹配异构排产数据（5 JSON 结构）；任务/方案/日志 schema 灵活 |
| 队列/进度 | Redis 7 + RQ | 轻量可靠；pub/sub 作进度总线跨进程可见（规避 threading.Event 跨进程失效） |
| Worker | Python + RQ | 与求解内核同进程内运行（solver-core 直接 import） |
| 前端 | React 18 + Vite + TypeScript | 类型安全、构建产物静态托管、组件化 Dashboard |
| 网关 | Nginx (alpine) | TLS 终止、静态托管、反代 API、单入口 |
| 部署 | Docker Compose + K8s 清单 | 单机快速验证 + 生产集群双形态 |
| 基础镜像 | python:3.14-slim | ortools 官方 wheel 验证支持 cp314 |

## 三、模块设计

### 1. solver-core（求解核心，`pip install -e` 可装）

```
solver-core/scheduler/
├── model.py        # 数据模型 + 数据体检 + evaluate + feasibility_check
├── cp_sat.py       # CP-SAT 精确建模（公式编号逐行注释）
├── heuristics.py   # 构造启发式 + ALNS 元启发
├── router.py       # 规模路由（数据决定模型）
├── evaluation.py   # 解质量评估（7 项指标）
├── visualize.py    # 甘特图/负载图/延误散点
└── __init__.py
```

**求解器路由**（`router.solve` 内建）：

| 订单数 n | 策略 |
|---|---|
| n ≤ 20 | CP-SAT 精确（time_limit=∞） |
| n ≤ 80 | 构造 + ALNS 300s |
| n ≤ 300 | 构造 + ALNS 900s |
| else | 构造 + ALNS 900s |

**CP-SAT 关键建模决策**（反幻觉审查定稿）：

- 序列相关 setup 用 `AddCircuit` + 弧 literal + `OnlyEnforceIf`（`AddTransitionTime` 在 9.15 不存在，已 `hasattr` 实机验证）；
- horizon 上界收紧为 Σp_j + (n−1) × max_s（Big-M 数值卫生）；
- null 切换对不建弧 → 禁止紧邻，允许中间配方绕行。

### 2. backend（FastAPI 服务）

```
backend/app/
├── main.py            # 入口 + /healthz + 路由注册
├── core/
│   ├── config.py      # pydantic-settings 配置（MONGO_URI/REDIS_URL/JWT_SECRET...）
│   ├── security.py    # bcrypt 密码哈希 + JWT 签发/校验 + API Token 生成
│   ├── redis.py       # Redis 客户端 + cancel_key/task_channel 工具
│   ├── rate_limit.py  # 限流中间件
│   ├── metrics.py     # /metrics 指标
│   └── deps.py        # 依赖注入（当前用户/租户解析）
├── db/mongo.py        # MongoDB 客户端 + collections 定义
├── models/schemas.py  # Pydantic 请求/响应模型
├── services/solver_service.py  # 数据集→DataModel 转换 + 同步求解
└── api/v1/
    ├── auth.py        # register/login/refresh/api-tokens
    ├── datasets.py    # 数据集 CRUD
    ├── tasks.py       # 任务提交/查询/日志/SSE/取消
    └── solutions.py   # 方案查询
```

### 3. worker（异步求解）

- RQ job 消费任务队列；`run_worker.py` 作为启动 wrapper（显式 `sys.path.insert`，规避 RQ `--path fork` 不可靠问题）；
- 求解状态机：`pending → running → succeeded / failed / cancelled`；
- 幂等：solution 以 `(task_id, engine)` 唯一键，worker 崩溃重试不重复写；
- 日志环形上限 MAX_LOG_LINES=10000 落库，可经 `/tasks/{id}/logs.txt` 下载；
- 取消：Redis 取消标志位，worker 每步检查。

### 4. frontend（React SPA）

```
frontend/src/
├── App.tsx            # 布局 + 路由
├── Dashboard.tsx      # 任务结果 Dashboard（状态机/SSE 事件/求解日志/优化分析）
├── ParamsPanel.tsx    # 求解参数表单（权重/求解器/时间预算）
├── Gantt.tsx          # 甘特图
├── LogPanel.tsx       # 求解日志面板
├── AnalysisPanel.tsx  # 优化分析（瓶颈/延误分布/负载均衡）
├── api.ts             # API 客户端（含 SSE 订阅）
└── types.ts           # TS 类型（与后端 schemas 对齐）
```

构建产物 `frontend/dist/` 由 nginx 静态托管。

### 5. deploy（部署）

```
deploy/
├── docker-compose.yml   # mongo / redis / api / worker / nginx 五服务
├── Dockerfile.api       # 国内镜像源（apt/pip 清华）+ appuser 非 root
├── Dockerfile.worker
├── nginx.conf           # TLS + 反代 /api + 静态托管
├── .env.example         # JWT_SECRET / ENVIRONMENT 模板
└── k8s/                 # 00-namespace ~ 30-nginx 全套清单（secret/configmap/mongo/redis/api/worker/nginx）
```

## 四、数据模型（MongoDB）

| Collection | 关键字段 | 说明 |
|---|---|---|
| users | email(unique), password_hash, tenant_id, role | 四级角色 |
| tenants | name, plan | 租户与订阅分级 |
| api_tokens | prefix, token_hash, name, tenant_id, revoked | API Token 双通道 |
| datasets | tenant_id, name, machines[], orders[], recipes[], switch_matrix, num_orders/num_machines/num_recipes | 5 JSON 合并入一个文档 |
| tasks | tenant_id, dataset_id, config{weights,solver,time_budget,seed}, status, timeline[], progress | 状态机 + 时间线 |
| solutions | task_id, engine, params, metrics{makespan,tardiness,completion,gap}, assignments[], gantt[], logs | (task_id, engine) 唯一幂等 |
| task_logs | task_id, lines[] | 求解日志环形缓冲 |

Pydantic 请求模型（`schemas.py`）：

- 认证：`RegisterRequest` / `LoginRequest` / `TokenResponse` / `ApiTokenCreate` / `ApiTokenOut`
- 数据集：`MachineIn{id,allowed_recipes,cleanup_time}` / `OrderIn{id,recipe_id,quantity,due_time,priority}` / `RecipeIn{id,processing_time}` / `SwitchMatrixIn{recipes,matrix int|null}` / `DatasetIn` / `DatasetOut`
- 任务：`TaskConfig{weights:(λ₁,λ₂,λ₃), solver:"auto|cpsat|alns", time_budget, seed}` / `TaskCreate` / `TaskOut`

## 五、API 设计

### REST 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/v1/auth/register | 注册（自动建租户） |
| POST | /api/v1/auth/login | 登录，返回 access+refresh 双令牌 |
| POST | /api/v1/auth/refresh | 刷新令牌 |
| POST/GET | /api/v1/auth/api-tokens | 创建/列出 API Token |
| POST | /api/v1/datasets | 上传数据集（201） |
| GET | /api/v1/datasets | 数据集列表 |
| GET | /api/v1/datasets/{id} | 数据集详情 |
| POST | /api/v1/tasks | 提交求解任务（202，异步） |
| GET | /api/v1/tasks | 任务列表 |
| GET | /api/v1/tasks/{id} | 任务详情（含状态/进度/时间线） |
| GET | /api/v1/tasks/{id}/logs.txt | 求解日志下载 |
| GET | /api/v1/tasks/{id}/events | **SSE 事件流** |
| DELETE | /api/v1/tasks/{id} | 取消/删除任务 |
| GET | /api/v1/tasks/{task_id}/solutions | 任务方案列表 |
| GET | /api/v1/solutions/{solution_id} | 方案详情 |
| GET | /healthz | 健康检查（容器探针） |

### SSE 事件流（tasks/{id}/events）

```
event: progress   data: {"type":"progress","stage":"running","progress":0.35,...}
event: log        data: {"type":"log","ts":...,"level":"INFO","msg":"..."}
event: done       data: {"type":"done","solution_id":"...","metrics":{...}}
event: failed     data: {"type":"failed","error":"..."}
```

Worker 写入 Redis pub/sub（channel=task_channel），API 订阅并转发 SSE；终态任务直接读库回放。

### 任务状态机

```
        ┌────────┐  提交   ┌─────────┐   Worker 领取  ┌─────────┐
        │pending │ ──────▶ │ running │ ─────────────▶ │succeeded│
        └────────┘         └─────────┘                └─────────┘
                              │   │                       │
                    Worker 异常│   │用户取消             失败│
                              ▼   ▼                       ▼
                          failed  cancelled            （终态，可回放）
```

## 六、安全设计

| 项 | 方案 |
|---|---|
| 密码存储 | bcrypt 哈希（非明文） |
| 会话鉴权 | JWT access + refresh 双令牌，Bearer 头携带 |
| 程序调用 | API Token 通道（明文仅创建时返回一次，库中存哈希） |
| 传输安全 | nginx TLS 终止（deploy/certs/ 自签证书，生产换 CA 证书） |
| 防滥用 | 全局限流中间件（rate_limit.py） |
| 多租户隔离 | 所有查询强制 tenant_id 过滤（deps.py 注入），文档级隔离 |
| CORS | 白名单配置 |

## 七、部署方案

### Docker Compose（单机快速部署）

```bash
cd deploy
cp .env.example .env      # 填 JWT_SECRET（仅首次；勿反复 cp 覆盖密钥）
docker compose up -d --build
# nginx: http://localhost:8080  https://localhost:8443
curl http://localhost:8080/healthz
```

服务拓扑：`mongo:7` + `redis:7-alpine` + `api` + `worker` + `nginx:alpine`（挂载 `frontend/dist` 与 `certs`）。

> Docker 构建注意事项：Docker Hub 受限网络需配置 registry-mirrors（DaoCloud 等）；Dockerfile 已内置国内 apt/pip 镜像源。

### Kubernetes（生产集群）

`deploy/k8s/` 全套清单：00-namespace → 01-secret（JWT 等）→ 02-configmap → 10-mongo（StatefulSet + PVC）→ 11-redis → 20-api（Deployment + Service + 探针）→ 21-worker → 30-nginx（Ingress/Service）。

### 环境变量

| 变量 | 说明 |
|---|---|
| MONGO_URI | mongodb://mongo:27017/or_scheduling |
| REDIS_URL | redis://redis:6379/0 |
| JWT_SECRET | 会话签名密钥（生产必须强随机） |
| ENVIRONMENT | dev / prod |

## 八、测试策略

### 1. 单元测试（tests/unit/，17/17 通过）

覆盖：数据加载与体检（空输入/缺文件/坏 JSON）、可行性预检、评估一致性、null 切换不可行检测、构造启发式（含 boundary 8 null 边界）、ALNS 单调性、CP-SAT L1/L2 最优性、规模路由。

### 2. 四层/五层测试（含性能数据）

| 层级 | 实例 | 方法 | status | 耗时 | 关键指标 |
|---|---|---|---|---|---|
| L1 toy | 3 机×5 单 | CP-SAT | OPTIMAL | 0.008s | gap=0，ΣT=82 |
| L2 boundary | 4 机×12 单（8 null） | CP-SAT | OPTIMAL | 24.7s | gap=0，ΣT=1270 |
| L3 medium | 8 机×50 单 | 构造+ALNS | FEASIBLE | 300s | ΣT=7292（优于 CP-SAT 7828） |
| L4 large | 20 机×200 单 | 构造+ALNS | FEASIBLE | 900s | ΣT=53169 |
| L5 massive | 30 机×500 单 | 构造+ALNS | FEASIBLE | 构造 0.3s + ALNS 234.8s | makespan 3256→2987（−8.3%） |

报告：`docs/test_reports/test_L1~L4.md`、`docs/test-reports/test_L5.md`。

### 3. 反幻觉质量红线

- 启发式方案附质量基准（L1~L3 对比精确解 gap）；无下界时 gap 如实标注 None；
- 每个约束/目标有公式编号，代码逐行标注（`# (n)`）；
- API 使用经 `hasattr` 实机验证（详见 `docs/solver-findings.md`）。

## 九、关键设计决策记录

| # | 决策 | 依据 |
|---|---|---|
| D1 | Python 3.14-slim 基础镜像 | ortools 官方 wheel 验证支持 cp314 |
| D2 | Gurobi 引擎默认不启用，仅留接口 | 需商业/学术 license |
| D3 | 取消/进度通道 = Redis 标志位 + pub/sub | fork 进程跨进程可见；threading.Event 跨进程失效已规避 |
| D4 | 一致性 = 幂等键 + 状态机 + 补偿 | 单实例 MongoDB 无跨集合事务，替代方案已定 |
| D5 | SSE 四段式（Worker→Redis→API→浏览器） | API 无状态，可水平扩展 |
| D6 | 序列相关 setup 用 AddCircuit+OnlyEnforceIf | AddTransitionTime 在 9.15 不存在（hasattr 实测） |
| D7 | L3 由 CP-SAT 时间限改为元启发 | 实测 CP-SAT 300s gap 90% vs ALNS 60s 更优（数据决定模型） |
