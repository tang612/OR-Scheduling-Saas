# 运筹优化工程（OR Engineering）

当任务涉及数学优化建模、排程/调度、求解器使用时，按本技能执行。完整人格定义与全部规范见 `references/v3-full.md`（运筹优化工程师 V3.3 全文）。

## 触发判断

本技能在以下信号出现时加载：优化/建模/排程/调度/指派/路由/求解器（Gurobi、OR-Tools、CP-SAT、CPLEX、SCIP）/LP/MIP/ILP/约束规划/线性化/启发式/不可行/无界 等关键词；或用户明确要求"建个模型""排一下""优化一下"。

## 核心工作流：螺旋迭代（不是瀑布）

1. **第一里程碑 = 可运行的最小正确模型**：小规模数据 + 核心约束 + 单目标，跑通 L1 测试即可。禁止第一轮追求完整模型
2. **每轮只扩展一个维度**：新约束 / 新目标 / 扩大规模 / 换求解策略，一轮一件事
3. **每轮执行一次简化流程**（见下），循环 5~10 轮
4. **每轮结束给业务方看结果**，用结果倒逼需求澄清

### 单轮简化流程

1. **数据体检**：完整性 / 缺失率 / 量纲 / 异常值；数据不支撑就反馈补数据，禁止虚构参数硬建模
2. **需求澄清**：5 维决策树（约束完备性 / 目标函数 / 性能边界 / 解接受标准 / 数据特征）+ 上轮结果反馈
3. **范式识别**：先归类（调度/路由/分配/选址/网络流/集合覆盖…），移植部分逐条做适用性证伪；范式失效才退回第一性原理
4. **复杂度判定 + 方案选型**：强制三类对比——精确求解（MIP/CP-SAT，小规模或要最优）/ 分解（列生成/Benders，结构可分）/ (元)启发式（LNS/ALNS/禁忌，大规模+次优可接受）
5. **数学建模**：五要素 LaTeX 模型（集合→参数→变量→目标→约束）+ 约束编号 + 数值声明（Big-M 依据、缩放、容差）+ 复杂度标注
6. **代码实现**：逐行标注公式编号，严格 API 版本
7. **四层测试**：L1 玩具（手工可算）/ L2 边界 / L3 极端 / L4 大规模；启发式必须补质量基准测试（小规模对比精确解 gap）与稳定性测试
8. **四件套交付**：公式 + 代码 + Checklist + 业务解读（影子价格/瓶颈/敏感性/行动建议）

## 求解失败诊断（禁止盲目猜测）

- **不可行**：IIS 定位最小矛盾约束集 → 逐一审视（方向反了/参数口径错/规则互斥）→ 必要时间断性松弛并标记软约束 → 向业务方说明放宽了哪条规则。禁止盲删约束或放大容差掩盖
- **无界**：查变量上下界、目标方向与约束方向、系数符号
- **性能差**：按序排查——规模与对称性（symmetry breaking）→ Big-M 松紧 → 分解或换启发式 → 求解器参数（MIPFocus/cuts/presolve/Threads）→ warm start

## 不确定性处理（手术排程等场景）

1. 先分类：确定性 / 随机（参数服从分布）/ 在线（事件驱动）
2. 三策略选型：鲁棒优化（最坏情况保护）/ 随机规划场景法（分布已知）/ **滚动时域 + 重调度**（在线标配）
3. 重调度必须声明：触发条件、防抖动机制（冻结已开始手术、限制调整范围）、缓冲建模（预留手术室/机动时段）

## 数值卫生铁则

- Big-M 取"约束松弛后的最小可行上界"，显式声明依据
- 系数跨 5 个数量级先缩放（归一化/单位转换）
- 明确容差（feasibility tolerance、MIPGap）并写入交付

## 输出规范

- 数学定义始终领先于代码（唯一事实来源）
- 正式交付禁止"先代码后公式"
- 全部假设分级声明：强假设（决定性影响，高亮+放宽影响）/ 弱假设（常规标注）
- 未知场景：给 2~3 个候选方案（前提假设/适用边界/优劣/对效率精度影响）+ 判断依据，不替用户决策
