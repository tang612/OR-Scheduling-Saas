# 运筹优化工程师人格部署方案对比

> 需求：**OR 人格常驻 OR-Scheduing-Saas 项目，平时保持通用**。
> 本目录存放三套候选方案的落地文件，选定后再部署到最终位置。

---

## 核心机制速览（选方案前必读）

| 机制 | 生效范围 | 是否项目级 | 常驻方式 |
|---|---|---|---|
| `.hermes.md`（项目规则文件） | 仅当前 git 仓库内 | ✅ 是 | 自动加载，零操作 |
| `AGENTS.md` | 仅当前目录（子目录不生效） | ✅ 是（弱） | 自动加载，零操作 |
| 自定义 `/personality` 预设 | **全局**（选择被全局记住） | ❌ 否 | 手动切换一次 + 记忆延续 |
| skill（按需加载） | 全局，但仅任务触发时加载 | ❌ 否 | 任务匹配才出现 |

**关键事实**：`display.personality` 是**全局记忆**的，不是项目级的——用 personality 方案，你在别的项目忘了切回，OR 人格会"泄漏"过去。真正满足"常驻项目 + 平时通用"的机制只有项目规则文件（`.hermes.md`）。

---

## 方案 A：`.hermes.md` 项目常驻人格（纯配置，零全局改动）

**文件**：`hermes-project-persona.md` → 部署为项目根目录 `.hermes.md`

- 在该 repo 内**任何子目录**运行 Hermes 时，自动以「资深运筹优化工程师」身份工作（浓缩内核：身份 + 三大思维底层 + 十铁则 + 四件套 + 手术排程专项规则）
- 离开该 repo → 自动恢复通用模式，**零残留**
- 不改全局配置、不装任何东西

| ✅ 优点 | ⚠️ 注意 |
|---|---|
| 完全自动，无手动操作 | 仅 Hermes 识别（若未来用 Claude Code/Codex 需另配 AGENTS.md） |
| 项目级边界精确（git root 即边界） | 内容是"身份 + 规则"，深度流程不在此承载 |
| 平时零影响 | — |

## 方案 B：`.hermes.md` 常驻身份 + `or-engineering` skill 深度流程（推荐）

**文件**：`hermes-project-persona.md` + `skill-or-engineering/`

- `.hermes.md` 只放**轻量常驻身份**（约 1KB，几乎不占上下文）
- 完整 V3.0 工作流（螺旋八步、四件套、四层测试、IIS 诊断、不确定性处理）封装为 skill
- 在项目内：身份常驻 ✅ + 遇到建模/排程任务时**自动按需加载**完整流程 ✅
- 在项目外：通用模式，但接到 OR 任务时 skill 仍会加载——**这是"知识"不是"人格"**，符合"平时通用"（通用 agent 也能调用专业知识），且 skill 不改变身份

| ✅ 优点 | ⚠️ 注意 |
|---|---|
| 常驻身份极轻量，深度流程按需加载，上下文最省 | 需要执行一次 skill 安装（一条命令） |
| 技能可随实战持续迭代（patch），越用越准 | skill 全局可见（知识不分项目，符合预期） |
| 完整 V3.0 永远随 skill 可用，不依赖项目文件 | — |

## 方案 C：自定义 `/personality` 预设（全局可切换）

**文件**：`config-personality-fragment.yaml` → 合并进 `$HERMES_HOME/config.yaml`

- `config.yaml` 增加 `agent.personalities.or-engineer` 预设（浓缩内核）
- 进项目时执行一次 `/personality or-engineer`，之后新会话自动延续；其他项目手动 `/personality none`

| ✅ 优点 | ⚠️ 注意 |
|---|---|
| 随时手动切换/关闭，多角色灵活 | **选择是全局记忆的，不是项目级的**——跨项目可能泄漏 |
| 聊天界面里 `/personality` 就能控制 | 需改全局配置 + 重启才生效 |
| 适合"多角色频繁切换"的场景 | 不满足"严格只在项目内生效" |

---

## 推荐

**首选方案 B**：项目身份用 `.hermes.md` 锁在项目边界内（满足"常驻项目 + 平时通用"），深度流程用 skill 按需加载（省上下文、可迭代）。方案 A 是它的轻量版（不想装 skill 就选 A）。方案 C 仅在你需要"一个 agent 频繁变脸"时才值得。

## 部署方式（选定后我来执行）

| 方案 | 部署动作 |
|---|---|
| A | 复制 `hermes-project-persona.md` → 项目根 `.hermes.md`（新会话生效） |
| B | A + 复制 `skill-or-engineering/` → `$HERMES_HOME/skills/` |
| C | 合并 config 片段 → 重启桌面应用 → `/personality or-engineer` |
